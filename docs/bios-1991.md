# Poisk BIOS 1991 (`src/rom/bios-1991.rom`)

A reverse-engineered description of the 8 KB system ROM `BIOS (C)1991, POISK`, built from
a control-flow-traced disassembly (ndisasm) and cross-checked against the emulator sources.

- Size: 8192 bytes, mapped at `F000:E000`–`F000:FFFF` (`BiosAddress = $FE000`)
- Byte checksum: `00h`
- Date string at `FFF5`: `14/02/91`; model byte at `FFFE`: `FEh` (PC/XT)
- Reset vector `FFF0`: `jmp F000:E016` (not the IBM `E05B`)

## Interrupt vectors

POST copies 30 words from `FEF3` to INT 05h onwards, with `CS` = `F000`. It then sets
NMI (INT 2) to `EEBD` and overwrites INT 1Dh with `0040:0098`.

|---|---|---|
| 02h | `EEBD` | NMI: video trap |
| 05h–07h | `EE60` | `iret` (no print screen) |
| 08h | `FEA5` | Timer (IRQ0) |
| 09h | `E987` | Keyboard; called in software by the matrix scanner |
| 0Ah–0Dh | `EE38` | Unexpected IRQ |
| 0Eh | `EC4D` | IRQ6: keyboard matrix scan |
| 0Fh | `EE38` | Unexpected IRQ |
| 10h | `F065` | Video |
| 11h | `F84D` | Equipment |
| 12h | `F841` | Memory size |
| 13h | `EE60` | `iret`; the FDC ROM (`E000:0000`) installs its own |
| 14h | `EE60` | `iret` (no serial) |
| 15h | `F859` | Cassette |

| 17h | `EE60` | `iret` (no printer) |
| 18h | `E13C` | Boot menu |
| 19h | `E6F2` | Bootstrap |
| 1Ah | `FE6E` | Time of day |

## I/O ports used

| Port | Dir | Use |
|---|---|---|
| `20h`/`21h` | out | 8259 PIC: ICW1 `13h`, ICW2 `08h`, ICW4 `01h`; EOI `20h` |
| `28h`/`29h` | in | NMI trap address latch (word). Bit 14 set = I/O trap, bit 15 set = write. Read at reset to clear the latch. |
| `2Ah` | in | NMI trap data byte (value written by a trapped `OUT`) |
| `40h`–`43h` | out/in | 8253 PIT. Ch0 mode 3, count 0 (18.2 Hz IRQ0). Ch1 mode 3, count 0 (18.2 Hz IRQ6). Ch2 speaker/tape tone. Ch0 is latched for tape edge timing. |
| `60h` | out | Keyboard matrix row strobe, **and** scancode latch read back by INT 9 |
| `61h` | out | Bits 0–1: speaker gate/data |
| `62h` | in | Bit 4: tape input; bit 5: PIT ch2 output |
| `63h` | out | PPI 1 control: `89h` |
| `68h` | out/in | Video control: bits 0–2 background colour (bit 0 also driven by РУС/ЛАТ), bit 3 NMI disable, bit 4 intensity, bit 5 palette, bit 6 display bank, bit 7 hi-res |
| `69h` | in | Matrix columns 0–7 (active low) |
| `6Ah` | in/out | In: matrix columns 8–11 (bits 0–3, active low). Out: high bits, written `10h` then `80h` (`40h` in mode 3) by set-mode; purpose unknown |

The ROM never writes `3D4h`/`3D5h`/`3D8h`/`3D9h` itself. Those ports exist only as NMI traps
for software that expects a CGA card.

## Power-on sequence

1. `E016` CLI, read `28h` to clear the trap latch, program PPIs (`63h`=`89h`, `6Bh`=`83h`),
   port `68h`=`88h`, `6Ah`=`10h`.
2. **Cartridge cold-start hook:** if `C000:0000` holds the bytes `AA 55` (the reverse of the IBM
   signature), jump to `C000:0003` immediately, before RAM is tested.
3. Test the first 64 KB with `55AAh`; `HLT` on any mismatch. Clear it. Stack `0000:03FF`.
4. Install vectors (see above). Copy the BDA template from `FA4D` to `40:00`. Set `40:3F`=1,
   `40:67`=6, `40:BC`=`FFh` (key click on).
5. Initialise the PIC and PIT ch0/ch1.
6. Checksum the BIOS; on failure beep 3 times and `HLT`.
7. Size memory from segment `1000h` up to `A000h` in 16 KB steps (write/invert/compare),
   clearing each block and adding 16 to `40:13` (template value 64).
8. `40:B0` = `0060h` (tape load segment). Set video mode 3.
9. Scan `C000`–`FDFF` in 512-byte steps for option ROMs with `55 AA`. Each one is
   checksummed over `[2]`×512 bytes (2 beeps on failure) and called at `seg:0003`.
10. `INT 19h`; if it returns, `INT 18h`.

BDA template (`FA4D`, 32 bytes): `40:08` = `0378h` (LPT1), `40:10` = `40ECh` (equipment:
80×25 colour, 1 printer, no floppy), `40:13` = 64 KB, `40:1A`/`40:1C` = `001Eh` (empty
keyboard buffer).

## Video: software CGA emulation

The Poisk has no CGA text hardware. Text modes are drawn as graphics by the BIOS.

### Mode setup (INT 10h AH=0)

Only modes 0–6 are accepted; mode 7 is ignored.

| Mode | Port `68h` | Displayed bitmap | Text buffer | Page size |
|---|---|---|---|---|
| 0, 1 (40×25) | `60h` (bank 1, palette 1) | `BC00:0000` 320×200 2 bpp | `B800:0000` | 2 KB |
| 2, 3 (80×25) | `C0h` (bank 1, hi-res) | `BC00:0000` 640×200 | `B800:0000` | 4 KB |
| 4, 5 (320×200) | `28h` (bank 0, palette 1, NMI off) | `B800:0000` | — | 16 KB |
| 6 (640×200) | `88h` (bank 0, hi-res, NMI off) | `B800:0000` | — | 16 KB |

In text modes the 16 KB text buffer is filled with `0720h` (NMI masked), then the 16 KB
bitmap bank is cleared. Graphics modes disable the NMI trap entirely.

### NMI trap handler (`EEBD`)

Reads the latch at `28h`/`29h`:

- **Memory write** (bit 14 clear): the address & `3FFEh` gives a text buffer cell. If it is on
  the active page (`40:62`) and row < 25, the BIOS reads the char/attribute word from
  `B800` and re-draws that one glyph into the bitmap, keeping the software cursor intact.
- **I/O read** (bit 14 set, bit 15 clear): `IN` from `3D5h` returns the copied CRTC
  register R0Ch–R0Fh (selected by `40:6B`) by patching the caller's saved AL.
- **I/O write** (bits 14+15 set), data from port `2Ah`:
  - `3D4h`: store the register index in `40:6B`.
  - `3D5h`: R0Ah/R0Bh → cursor shape (`40:61`/`40:60`); R0Ch → `40:9A` and *select page*
    (value >> 3) with a full re-draw; R0Dh → `40:9B`; R0Eh/R0Fh → `40:99`/`40:98`, then
    convert to row/column and set the cursor position.
  - `3D8h`: only when bit 3 (video enable) is **clear** and bits 0–4 are not all zero, decode
    the CGA mode-control bits into a BIOS mode number and, if it differs from `40:49`, run
    INT 10h set-mode. A write with the enable bit set, usually the last write of a mode
    switch, is ignored.
  - `3D9h`: merge bits 0–2, 4, 5 (background, intensity, palette) into port `68h`.

### Glyph rendering (`F55F`)

Characters `00h`–`7Fh` come from `F000:FA6E`, `80h`–`FFh` from the far pointer at INT 1Fh.

- **80 columns:** one byte per glyph row. The hardware shows 7 pixels (bits 6–0); bit 7 is a
  colour flag. Attribute `70h`–`7Fh` is drawn inverted. In mode 3, any attribute with bits
  `38h` set gets bit 7 (the highlight colour); mode 2 never sets it.
- **40 columns / modes 4–5:** each glyph row is expanded to 2 bpp using the foreground colour.
- **Mode 6:** direct copy; XOR when attribute bit 7 is set.

INT 10h AH=9/0Ah write the text buffer with the NMI masked and render directly, so only
direct writes to `B800` pay for an NMI. Text scrolling (AH=6/7) moves both the text buffer
and the bitmap. AH=8 in text modes reads back from the text buffer.

### Cursor

The cursor is drawn by XOR into the bitmap. INT 8 blinks it every 4 ticks (`40:67`
countdown, phase in `40:68`), unless the cursor is disabled (`40:60` & `3000h`) or a
graphics mode is active.

## Keyboard

### Matrix scanner (INT 0Eh, IRQ6 from PIT ch1)

1. `out 60h,FFh` (all rows) and read `69h`/`6Ah`. If no key is down, release every key
   still held and set `40:C2`=`FFh`.
2. Otherwise strobe rows `80h`, `40h`, … `01h`, read 12 columns (inverted), and compare
   with the stored row state at `40:C5`–`40:D4` (one word per row).
3. For each changed bit, look up the scancode (`EDC8` via `EE28`), **write it to port `60h`
   and execute `INT 9`** (break codes have bit 7 set).
4. Autorepeat: initial delay 6 scans, then every 2 (`40:BD`, key `40:BE`, row `40:C0`).
5. Key click: after each make code, unless it is a shift key, beep briefly when `40:BC`=`FFh`.
   Every F4 make code (`3Eh`) toggles `40:BC`.

**РУС/ЛАТ key (`55h`):** sent to INT 9 as Ctrl (`1Dh`). If it is pressed and released with
no other key in between, it toggles `40:BB` (`FFh` = РУС) and port `68h` bit 0.

### Matrix → scancode table (`EDC8`)

are port `6Ah` bits 0–3. `--` = no key.

### INT 9 (`E987`)

IBM PC/XT handler with these Poisk changes:

- Scancode `54h` is a dedicated Pause key (same path as Ctrl+NumLock).
- In РУС mode (`40:BB`=`FFh`) the extra keys produce CP1125 characters directly, with
  Shift/CapsLock choosing the case: KP+ (`4Eh`) → ё/Ё (`F1h`/`F0h`), KP- (`4Ah`) → є/Є
  (`F5h`/`F4h`), `56h` → і/І (`F7h`/`F6h`), `58h` → ї/Ї (`F9h`/`F8h`). In ЛАТ mode `56h`
  and `58h` are ignored.
- With CapsLock on, Shift does not lowercase Latin letters (`add al,0` at `EC06`, where the
  XT has `add al,20h`).
- Ctrl+Alt+Del stores `1234h` in `40:72` and jumps to `E016`.
- Ctrl+ScrollLock → INT 1Bh; Shift+PrtSc → INT 5 (which is an `iret`).
- Full buffer: beep.

### INT 16h (`E82E`)

AH=0 read, AH=1 peek, AH=2 shift flags; anything else returns unchanged. AH=0/1 pass the key
through the РУС translation (`E7EB`) when `40:BB`=`FFh`: ASCII `22h`–`7Eh` with a scancode
of `01h`–`35h` is replaced from `E731` (CapsLock off) or `E78E` (CapsLock on). The layout is
Russian ЙЦУКЕН, with `/` → ґ and `?` → Ґ.

## Cassette (INT 15h)

| AH | Address | Function |
|---|---|---|
| 0 | `F888` | Motor on: no-op (`ret`) |
| 1 | `F889` | Motor off: no-op |
| 2 | `F88A` | Read block: `ES:BX` buffer, `CX` bytes; returns `DX` = bytes read, CF/AH status |
| 3 | `F982` | Write block: `ES:BX`, `CX` |
| 4 | `FF29` | Find and load file: `DS:BX` = 8-byte name, `ES` = load segment |
| 5 | `FF7B` | Save file: `DS:BX` = 17-byte header, `ES:0000` = data (see bugs) |
| >5 | | `AH=86h`, CF=1 |

Status codes in AH (CF=1): 1 = CRC error, 2 = bad bit timing (data lost), 3 = Esc pressed,
4 = no data found.

**Signal format** (IBM PC cassette compatible):

- Bits are one PIT ch2 square-wave cycle: period `04A0h` for 1, `0250h` for 0.
- Write: 2048 one-bits of leader, one 0 bit, sync byte `16h`, then 256-byte blocks, each
  followed by its inverted CRC-CCITT (16 bits, init `FFFFh`, checked against `1D0Fh`), then
  32 one-bits of trailer.
- Read: edges on port `62h` bit 4 are timed with PIT ch0 (`40:A8`). The threshold is
  `06F0h` ticks per bit pair. Up to 7 attempts to find the leader.
- Esc aborts reads and writes: `out 60h,08h` (row 3), test port `69h` bit 5.

**File format** (IBM Cassette BASIC layout, documented in `bios_p.utf8/RWCAS.ASM`): a header
block, then a data block of the given length.

| Offset | Field |
|---|---|
| `00h` | `A5h` header marker |
| `01h`–`08h` | Name, space-padded |
| `09h` | Type: `00h` BASIC text / data, `01h` memory image (BSAVE), `40h` BASIC ASCII, `80h` BASIC tokenized, `A0h` BASIC protected |
| `0Ah` | Data length (word) |
| `0Ch` | Load segment (word) |
| `0Eh` | Load offset (word) |
| `10h` | `00h` end marker |

AH=4 reads only the first 12 bytes of the header block. It ignores the type and the load
address and always loads to `ES:0000`.

## Boot menu (INT 18h, `E13C`)

Sets mode 1, prints the copyright and a line of `═`, then:

```
F1-Работа с кассетой
F2-Работа с ПЗУ
```

- **F1:** prompt `Имя файла:` (8 characters, Esc returns, Backspace edits), then
  `Вкл. магнитофон, нажмите (ВК)`; wait for Enter. INT 15h AH=4 loads the file to
  `[40:B0]:0000` (`0060:0000`), printing `Найден файл: <name>` for every header seen and
  `-Загрузка!` on a match. It then prints `Выкл. магнитофон`. On success it prints
  `Запуск (ВК)`; Enter jumps to `0060:0000`, any other key returns to the menu.
  On failure it prints `Ошибка чтения!` or, if a key was pressed, `Чтение прервано!`.
- **F2:** if `C000:0000` starts with `E9h` (near `jmp`), set mode 2 and jump to `C000:0000`.

## INT 19h (`E6F2`)

Runs only if equipment bit 0 is set; otherwise it returns. The bit is set by the FDC option
ROM (`fdc-b504.rom`, source `bios_p.utf8/DRV20.ASM`) when it installs INT 13h. It sets mode 3, prints the copyright, and makes up to 4 attempts to reset drive 0
and read cylinder 0, head 0, sector 1 to `0000:7C00`, then jumps there.

## Other services

- **INT 1Ah:** AH=0 read ticks (`40:6C`/`40:6E`, overflow flag `40:70`), AH=1 set ticks.
  No real-time clock.
- **INT 8:** increments ticks, wraps at `1800B0h`, runs the cursor blink, calls INT 1Ch, EOI.
- **Unexpected IRQ (`EE38`):** reads the ISR, masks that line in the IMR, sends EOI and stores
  the ISR in `40:AC` (the IBM BIOS uses `40:6B`, which here holds the CRTC index).

## Bugs and quirks

- **INT 15h AH=5 never returns correctly.** It ends with `push ds` / `ret`, so it jumps to
  `F000:<caller's DS>`. It also takes the data length from `[BX+9]` after the header write;
  the header puts the length at offset `0Ah`, and the write routine advances BX. The 1989 ROM
  has the same code. The 26.02.90 source revision (`bios_p.utf8`) fixes the length (saves BX,
  uses `[BX+10]`) but keeps the `push ds` / `ret`.
- **Warm boot is a cold boot.** Ctrl+Alt+Del sets `40:72`=`1234h`, but POST never checks it,
  always runs the RAM test and clears memory.
- **INT 20h–22h get garbage**, because the vector copy is 30 words long but the table is 27.
  DOS overwrites them.
- **Shift does not undo CapsLock** for Latin letters (see INT 9).
- **Cartridge hooks use two signatures:** `AA 55` at `C000:0000` (checked before the RAM test,
  enters at `+3`) and the standard `55 AA` option ROM scan (later, called at `+3` with a far
  return to `FFEB`). The F2 menu item instead requires `E9h` at `C000:0000`.
- A dead `cmp al,45h` at `EA34` is left over from patching the XT pause logic to use `54h`.
- An option ROM that fails its checksum makes the scan skip an extra 512 bytes.

## Differences from the emulator

Found by comparing the ROM with `src/keyboard.pas` and `src/videocontroller.pas`:

- `Port68Map` has `keyNone` at row 0 col 4 and row 6 col 4, which the ROM maps to KP+
  (`4Eh`) and KP- (`4Ah`).
- Row 4 col 7 (`58h`, ї/Ї) and row 7 col 7 (`56h`, і/І) are unmapped (`keyNone`), so
  those Ukrainian letters cannot be typed.
- Row 5 col 0 is right Shift (`36h`) and col 7 is left Shift (`2Ah`) in the ROM; the
  emulator has them the other way round. This only affects the INT 16h AH=2 flags.
- The emulator offsets the displayed image by CRTC R0Ch/R0Dh. In text modes this BIOS
  handles an R0Ch write as a page switch and re-draws the bitmap itself, so a program that
  writes R0Ch may be shifted twice. Not verified against real hardware.
