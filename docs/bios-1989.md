# Poisk BIOS 1989 (`src/rom/bios-1989.rom`)

A description of the original Poisk 8 KB system ROM `POISK (C) 1989 UkSSR`, built from a
control-flow-traced disassembly (ndisasm) and matched against the assembler sources in
`bios_p.utf8/`. Routine and variable names below are the ones used in those sources.

- Size: 8192 bytes, mapped at `F000:E000`–`F000:FFFF`
- Byte checksum: `00h` (adjusting byte at `FFFF` = `A1h`)
- Date string at `FFF5`: `10/07/88`; byte at `FFFE`: `00h` (the source has `FFh`)
- Reset vector `FFF0`: `jmp F000:E016`

For the later ROM see [bios-1991.md](bios-1991.md). The hardware is the same; most
differences are in the keyboard layout, the character set and the video trap handler (see
[Differences from the 1991 ROM](#differences-from-the-1991-rom)).

## Sources (`bios_p.utf8/`)

`BIOS.ASM` ("ver 26.02.90", "ОТКРЫТА ПАМЯТЬ (96К)") includes 28 modules in ROM order. The
files were recovered from an assembler listing (`bios.lst`) by `ASMI.C`, which cuts the
listing at each `INCLUDE`. As a result, every module's `ORG` sits at the end of the
previous file, and `RESTART.ASM` carries an unused `AN_STR` procedure after `CODE ENDS`.
Most files are CP866; a few were converted to UTF-8. No macros or conditional assembly are
used, but the sources need MASM-compatible syntax to rebuild.

### How closely the sources match the ROM

Aligning each module's instruction stream against the ROM disassembly matches 2378 of the
2400 source instructions (99.1%). All remaining differences are code that the source **has**
and the ROM **lacks**, so the ROM predates the sources:

| Module | Source-only change | ROM location |
|---|---|---|
| `INT_TIME.ASM` | Skip cursor blink when `CURSOR_MODE` = `2000h`, marked "15.01.90" | after `EC38` |
| `NMISER.ASM` | Wrap the trapped offset (`DI and 0FFFh` / `1FFFh`) before drawing | before `EEA6` |
| `INT10_A.ASM` | 80-column cursor keeps the colour bit (`and 7Fh` / `or 80h`) | `F237`–`F23B` |
| `RWCAS.ASM` | `FILE_WRITE` saves BX around the header write and reads the length from `[BX+10]`; the ROM has `[BX+9]` and no save | `F00D`–`F00F` |

All data blocks match exactly (strings, both keyboard tables, the Cyrillic font, the BDA
template, the mode table, `LN_KEY1`), except the `00h`–`7Fh` font (`CRT_GEN.ASM`). There, 17
control-character glyphs (`02h`–`06h`, `08h`, `0Ah`, `0Dh`, `10h`, `11h`, `17h`, `1Ah`–`1Fh`)
have a one-pixel gap in column 3 of their solid areas in the source; the ROM's are solid.

`DRV20.ASM` is not part of `BIOS.ASM`: it is the source of the floppy controller ROM (see
[FDC option ROM](#fdc-option-rom-fdc-b504rom)). `INT10_BN.~AS` is an editor backup.

## Power-on sequence (`TEST.ASM`)

1. CLI, read `TRAP_A` (clear NMI trigger), `PPIC`=`89h`, `SCR_MODE`=`88h`, read `TRAP_A`,
   `KEY_SERV_MODE`=`83h`.
2. If `C000:0000` holds the word `55AAh` (bytes `AA 55`), jump to `C000:0003`
   ("привилегированное ПЗУ", a privileged ROM) before anything else.
3. Clear and verify the 96 KB of base RAM: `0000:0000`–`FFFE` (CX = `FFFFh`, so the last byte
   of the first 64 KB is skipped) and `0800:8000`–`FFFF`. `HLT` on an error in the first part,
   4 beeps + `HLT` on an error in the second.
4. Stack `0000:03FF`. Install vectors. Copy `TEST_TABLIC` (`EC59`) to `40:00`.
5. Memory sizing: starting at segment `4000h`, write/invert/compare `5AA5h` at offset 0 of
   each 256 KB step (`4000h`, `8000h`, …) and add 256 to `MEMORY_SIZE` for each hit. With the
   template's 96 KB this gives 96, 352 or 608 KB.
6. `MOTOR_STATUS`=1, `FBEEP`=`FFh` (key click on). Initialise the PIC and PIT ch0/ch1.
7. Set video mode 3, checksum the BIOS (3 beeps + `HLT` on failure).
8. Clear `TRACK_PTR`, set `LOAD_ADDR`=`0060h`, STI.
9. Scan `C000`–`FDFF` in 512-byte steps for `55 AA` option ROMs (`ROM_INIT`).
10. `INT 19h`, then `INT 18h`.

`TEST_TABLIC`: no serial ports, LPT1 = `378h`, `EQUIP_FLAG` = `40ECh`, `MEMORY_SIZE` = 96,
`IO_RAM_SIZE` = 64, keyboard buffer at `1Eh`.

## Video

### Modes (`SET_MODE`, `VIDEO_PARMS`)

| Mode | Port `68h` | Page size |
|---|---|---|
| 0, 1 (40×25) | `40h` `CHAR_40_MODE` | 2 KB |
| 2, 3 (80×25) | `C0h` `CHAR_80_MODE` | 4 KB |
| 4, 5 (320×200) | `28h` `MED_RES_MODE` | 16 KB |
| 6, 7 (640×200) | `88h` `HIGH_RES_MODE` | 16 KB |

Text modes keep the character/attribute buffer at `B800:0000` (`START_BUFFER`) and draw into
the bitmap at `BC00:0000` (`EXTRA_BUFFER`). Graphics modes draw directly at `B800:0000`
with the NMI disabled.

**`INT 10h` AH=0 with AL ≥ 8 is `CURSOR_BLINK`, not a mode set.** It XORs the cursor into the
bitmap unless `CURSOR_ON` = `0Fh`. `TIMER_INT` calls it with `AX` = `0008h` every
`CURSOR_TIME` (4) ticks, unless `CURSOR_MODE` = 0.

### NMI trap handler (`NMI_SERVICE`, `EE35`)

- **Memory write** (`TRAP_A` bit 14 clear, `MWTC_ROUTINE`): take the word at
  `B800:(addr and 3FFEh)`, compute page, row and column, and if the page is `ACTIVE_PAGE`,
  draw the glyph into the bitmap (`S1B`), removing the cursor first if it is there.
- **I/O read** (`IORC_ROUTINE`): always returns `FFh` in the caller's AL.
- **I/O write** (`IOWC_ROUTINE`), data from `TRAP_D`:
  - `3D4h`: store the index in `REG_6845` (`40:84`).
  - `3D5h`: R0Bh → `CURSOR_MODE` low byte, R0Ah → high byte, R0Eh → `CURSOR_POS_H`,
    R0Fh → `CURSOR_POS_L`; on R0Fh convert to row/column and call `SET_CPOS` for
    `ACTIVE_PAGE`. R0Ch/R0Dh (start address) are ignored.
  - `3D8h`: only when bit 3 (video enable) is **clear** and bits 0–4 are not all zero: decode
    text/graphics, 40/80 and colour bits into a BIOS mode and call INT 10h if it differs from
    `CRT_MODE`. A write with the enable bit set, the usual final write, is ignored.
  - `3D9h`: merge bits 0–2, 4, 5 into `SCR_MODE`, keeping bits 3, 6, 7.

## Keyboard

### Matrix scanner (`SCANINT`, INT 0Eh)

- `out 60h,FFh` and read `69h`/`6Ah`. If no key is down and none was down before (`EMPTY`),
  return at once.
- A re-entry guard (`W_SCAN`, "29.10.88") stops nested scans.
- For each row (`80h` down to `01h`), invert the columns, compare with `KB_STAT`, and handle
  each changed key: a press calls `SEND_CODE` and starts autorepeat (`LAST`, `TIME`: first
  delay 8 scans, then every 2); a release sends the code with bit 7 set.
- `C_INT9` writes the scancode to `LINE_SEL` (port `60h`) and executes `INT 9`.

`SEND_CODE` / `C_OUT60` rules for a table entry:

| Entry | Meaning |
|---|---|
| `00h` | No key |
| `01h`–`7Fh` | Plain scancode; click on every press including repeats |
| `80h`+code | Modifier: no click on autorepeat |
| `C8h`–`DAh` | Sent as `E0h`, code ("14.02.89"); none are used in the table |
| `DBh` (`RUS_KEY`) | Toggle `RUSS`; never reaches INT 9 |
| `DCh` (`SHIFT2_KEY`) | Toggle `SHIFT2` and `RUSS` on press and on release; never reaches INT 9 |
| `F1h`–`FFh` (−15…−1) | Special key `S1`–`S15` from `LN_KEY1` |

A special key sends the scancode for the current shift state (plain, Shift held, `SHIFT2`
on). If that code's bit 7 is set, it is wrapped in a fake LShift press or release so the
character comes out with the opposite case. The code sent is remembered in `MEM_KEY` so the
release matches. F4 (`3Eh`) toggles the key click (`FBEEP`) on every press.

### Matrix table (`LINE1`–`LINE8`, `E7BD`)

Rows are selected with `out 60h, 1<<row`. Columns c0–c7 are port `69h` bits 0–7, c8–c11 are
port `6Ah` bits 0–3. Letters are shown by their Latin key; in РУС mode they produce Cyrillic
(see below). `Х Ъ Ж Э Ю Б Ё` are the extra scancodes `54h`–`5Ah` ("03.02.88").

### INT 9 (`KB_INT`, `E987`)

IBM PC/XT-style handler (keyboard comments by М. Б. Батьковский, 06.01.89) with these Poisk
additions:

- An `E0h` prefix is stored in `SCAN_CODE_OLD`; the next code is treated as an extended key.
- **Cyrillic is produced here** (`SERVICE_RUSS`). When `RUSS` = `TRUE` and there is no
  Ctrl/Alt, scancodes in `KT_RUS0` (`10h`–`19h`, `1Eh`–`26h`, `2Ch`–`32h`, `54h`–`5Ah`) are
  mapped through `LR` = `ЙЦУКЕНГШЩЗФЫВАПРОЛДЯЧСМИТЬХЪЖЭЮБ` + `F0h` (Ё). Lowercase is
  +`20h`, and +`50h` for р–я, Ё → ё. The case follows Shift XOR CapsLock.
- Shift+PrtSc → INT 5 (an `iret`); Ctrl+NumLock → pause; Ctrl+Alt+Del sets `RESET_FLAG` =
  `1234h` and restarts at `E016`.

### INT 16h (`KEYBOARD_IO`, `E82E`)

AH=0 read (by polling AH=1), AH=1 peek (ZF = empty, returns with `RET 2`), any other AH
returns `KB_FLAG`. There is no translation at this level.

## Character set

The upper font (`ALTC`) is CP866 ("альтернативная кодировка"): `80h`–`AFh` А–п, `B0h`–`DFh`
box drawing, `E0h`–`EFh` р–я, `F0h`/`F1h` Ё/ё. `F6h`/`F7h` are drawn as →/←; the menu title
uses them around `"ПОИСК"`. There are no Ukrainian letters.

## Cassette (INT 15h, `CASSETTE_IO`)

| AH | Address | Function |
|---|---|---|
| 0, 1 | — | Motor on/off: return immediately |
| 2 | `F891` | Read block: `ES:BX`, `CX` bytes |
| 3 | `F9D3` | Write block: `ES:BX`, `CX` bytes |
| 4 | `EFB4` | `FILE_READ`: `DS:BX` = 8-byte name, load to `ES:0000` |
| 5 | `EFFE` | `FILE_WRITE`: `DS:BX` = 17-byte header, data at `ES:0000` |
| other | | `AH=80h`, CF=1 |

The signal and block format are the IBM PC cassette format: bit "1" is a 1184-count
(`04A0h`) PIT period (~1 ms), "0" is 592 counts. Blocks are 256 bytes with a CRC
(`CRC_GEN`, `CRC_REG` at `40:69`). Half-bit timing is measured by `READ_HALF_BIT` with PIT
ch0 (`EDGE_CNT`, `LAST_VAL`).

`BREAK_TEST` strobes all rows and tests port `69h` bit 7 (column c7). Any key in that column
aborts a read: Esc, Caps, the right-hand LShift, `\`, KP1, KP2 or KP6. The source comment
says "ESC, TAB or CTRL".

### File header (from `RWCAS.ASM`)

| Offset | Field |
|---|---|
| `00h` | `A5h` header marker |
| `01h`–`08h` | Name, 1–8 characters (Cyrillic allowed) |
| `09h` | Type: `00h` BASIC text / data, `01h` memory (BSAVE), `40h` BASIC ASCII (SAVE ,A), `80h` BASIC tokenized, `A0h` BASIC protected (SAVE ,P) |
| `0Ah` | Data length (word) |
| `0Ch` | Segment (word) |
| `0Eh` | Offset (word) |
| `10h` | `00h` end marker |

`FILE_READ` reads 12-byte header blocks until byte 0 is `A5h` and the name matches. It prints
`Файл найден!`, then reads the data block (length from offset `0Ah`) to `ES:0000`.

## Boot menu (`MONITOR`, INT 18h)

Mode 1, then:

```
→ "ПОИСК" ←

F1 - Работа с кассетой

F2 - Работа с ПЗУ

Выберите РЕЖИМ
```

- **F1** (`READ_CAS`): `Введите имя файла:` (8 characters, Esc restarts input), then
  `Вкл.  магнитофон, нажмите (BK)`; on Enter, INT 15h AH=4 loads the file to
  `LOAD_ADDR:0000` (`0060:0000`). Then `Запускать?`: `N`, `n`, `Н` or `н` returns to the menu,
  anything else does a far return to `0060:0000`. A read error shows `Ошибка чтения ***`.
- **F2**: if `C000:0000` (`KARTRIDJ`) starts with `E9h`, set mode 2 and jump there.

## Other services

- **INT 19h** (`BOOT_STRAP`): only if `EQUIP_FLAG` bit 0 is set (by the FDC ROM); 4 attempts
  to read drive 0, cylinder 0, head 0, sector 1 to `0000:7C00` (`BOOT_LOCN`), otherwise `iret`.
- **INT 8** (`TIMER_INT`): ticks (`TIMER_LOW`/`TIMER_HIGH`, midnight at `1800B0h`,
  `TIMER_OFL`), cursor blink, INT 1Ch, EOI.
- **INT 1Ah** (`TIME_OF_DAY`): AH=0 read / AH=1 set ticks. No clock chip.
- **`HARD_RETURN`**: reads the ISR, masks that IRQ, sends EOI, stores the ISR in `INTR_FLAG`
  (`40:6B`).
- **INT 11h / 12h**: return `EQUIP_FLAG` / `MEMORY_SIZE`.

## BIOS data area (`EQU.ASM`, segment `DATA` at `40h`)

The IBM part (`40:00`–`40:74`) keeps the IBM PC names and offsets, including the cassette
`EDGE_CNT` (`40:67`) and `CRC_REG` (`40:69`) and `INTR_FLAG` (`40:6B`). The Poisk extension
starts at `DATA_ORG` = `40:80`:

| Address | Name | Use |
|---|---|---|
| `40:74` | `LOWLIM` | Tape: minimum "1" half-period |
| `40:80` | `CURSOR_COUNT` | Ticks until the next blink |
| `40:81` | `CRT_MODE_SAFE` | Saved mode |
| `40:82` | `CURSOR_ON` | Cursor drawn flag |

## Bugs and quirks

- **INT 15h AH=5 (`FILE_WRITE`) never returns correctly.** It ends with `PUSH DS` / `RET`
  (also in the source), so it jumps to `F000:<caller's DS>`. It also reads the data length
  from `[BX+9]` after AH=3 has advanced BX past the 17 header bytes; the source revision
  fixes this part only.
- **INT 10h AH=0 with AL ≥ 8 toggles the cursor** instead of being ignored, so a program
  probing for EGA/VGA modes gets cursor garbage, not a mode change.
- **CGA mode-register writes with the video-enable bit set are ignored** (see the NMI handler).
- **Warm boot is a cold boot**: `RESET_FLAG` = `1234h` is never checked.
- **INT 20h–22h get garbage** from the 30-word vector copy.
- **INT 1Dh points to the 8-byte mode → port `68h` table**, not to 6845 parameters.
- **Tape abort** reacts to any key in matrix column c7, not specifically Esc.
- **The first RAM clear skips one byte** (`0000:FFFF`), since CX = `FFFFh`.

## Differences from the 1991 ROM

The 1991 ROM matches only about 60% of these sources' instructions. The keyboard scanner,
INT 9 and the cassette file code were rewritten or moved.

| Area | 1989 | 1991 |
|---|---|---|
| Copyright / date / `FFFE` | `POISK (C) 1989 UkSSR`, `10/07/88`, `00h` | `BIOS (C)1991, POISK`, `14/02/91`, `FEh` |
| Character set | CP866, no Ukrainian | CP1125 (Ґ Є І Ї) |
| Keyboard layout | GOST: digits on Shift, SHIFT2 key, dedicated Х Ъ Ж Э Ю Б Ё keys | PC-like: same matrix positions read as a standard layout plus і/ї/є/ё |
| РУС/ЛАТ | Separate key, code `5Bh`; SHIFT2 `5Ch` | Code `55h`, tap = toggle, hold = Ctrl |
| Cyrillic translation | INT 9 (by scancode) | INT 16h (by ASCII) |
| RAM test / sizing | Clear+verify 96 KB, 256 KB steps from `4000h` | 64 KB pattern test, 16 KB steps from `1000h` |
| NMI trap | No reads (`FFh`), no start address | Reads R0Ch–R0Fh, R0Ch selects page |
| INT 10h AH=0 AL ≥ 8 | Cursor blink | Ignored (AL ≥ 7) |
| INT 15h dispatch / error | `dec ah` chain, `AH=80h` | Jump table, `AH=86h` |
| Menu | "Выберите РЕЖИМ", `Запускать?` (Y/N) | Shorter text, `Запуск (ВК)`, prints every header found |
| INT 1Dh | `F0B4` table | Overwritten with `0040:0098` |

The physical key positions are interpreted differently by the two ROMs. Under the 1989 ROM
the 1991 F1 position gives F2, the 1991 digit keys give GOST punctuation, and so on.

## Emulator notes

- The emulator defaults to the 1991 interpretation of the matrix. With `bios-1989.rom` and
  the default layout, the host keys produce the 1989 assignments above (for example, host F1
  gives F2, host Esc gives F1, host Pause gives Esc), and SHIFT2 (row 5 c5) is reached through
  host Left Alt.
- `--keyboard=1989` switches `src/keyboard.pas` to the `LINE1`–`LINE8` matrix and maps host
  keys by label: function keys, Esc, Ctrl, Alt, PrtSc, ScrLk, NumLk, KP+, KP- and
  letters go to the 1989 key of the same name. РУС/ЛАТ is host Right Ctrl and SHIFT2 is host
  Right Alt. Х Ъ Ж Э Б Ю Ё are on host `[ ] ; ' , . /`.
  The host digit row gives the GOST keys whose Shift digit matches (host `1` → S7, `2` → S6,
  `3` → S8, `4` → S5, `5` → S9, `6` → S10, `7` → S2, `8` → S3, `9` → S12, `0` → S11), plus
  `` ` `` → S4, `-` → S15, `=` → S13 and KP* → S1. This is the Russian typewriter layout. The
  `;` key at row 6 c4 and CapsLock have no host key.
- The 96 KB base and 256 KB sizing steps happen to give the right total for the emulator's
  128 KB and 640 KB configurations (96 and 608 KB, the video RAM being excluded).

## FDC option ROM (`fdc-b504.rom`)

`bios_p.utf8/DRV20.ASM` is the source of the 2 KB floppy ROM mapped at `E000:0000`. Its code
matches the ROM's first 0418h bytes (514 of 516 instructions; the two differences are
alignment artefacts).

- Header `55 AA 03` (1.5 KB). `DISK_INIT` at offset 3 sets `EQUIP_FLAG` bit 0 and points
  INT 13h at `DISKETTE_IO`.
- The controller is a WD1793-type chip on ports `C0h` (command/status), `C1h` (track), `C2h`
  (sector), `C3h` (data), `C4h` (write: drive select, motor, side, density, reset; read:
  INTRQ/DRQ) and `C6h` (motor state).
- Bytes `0418h`–`05FFh` are not referenced by the driver and look like leftover compiled C
  code from the build buffer; they are covered by the checksum (`00h` over `0`–`5FFh`).
  `0600h`–`07FFh` is zero.
